# API reference

Base URL (local): `http://127.0.0.1:8000`. Interactive docs: `/docs` (Swagger UI) and `/redoc`. The machine-readable schema is `packages/api-client/openapi.json`, regenerated by `python scripts/export_openapi.py`.

All routes except `/health` live under `/api/v1`. If `API_KEY` is set on the server, send `X-API-Key: <key>`. Errors always look like:

```json
{"error": {"code": "not_found", "message": "No such job", "details": null}}
```

## Flashcard review example

```bash
curl -X POST http://127.0.0.1:8000/api/v1/cards -H 'Content-Type: application/json' \
  -d '{"front":"What does LIFO stand for?","back":"Last in, first out."}'
# {"id":1,"interval_days":0,"ef":2.5,"repetitions":0,...,"due_at":<now>}
curl -X POST http://127.0.0.1:8000/api/v1/cards/1/review -H 'Content-Type: application/json' -d '{"grade":4}'
# {"id":1,"interval_days":1,"repetitions":1,"due_at":<tomorrow>,...}
```

## `POST /api/v1/ask`

Request:

```json
{
  "question": "How does a hash table handle collisions?",
  "k": 3,
  "mode": "technical",
  "model": null,
  "temperature": 0.2,
  "include_prompt": false,
  "no_cache": false
}
```

`mode` is the study style (technical, interview prep, quick summary). Response (abridged):

```json
{
  "answer": "A hash table has to deal with collisions ... [hashing.md]",
  "chunks": [
    {"doc": "hashing.md", "page": null, "end_page": null, "score": 0.62,
     "text": "Hash Tables > Collisions\nA collision occurs when ...", "url": null, "citation_url": null}
  ],
  "citations": [{"label": "hashing.md", "doc": "hashing.md", "page": null, "status": "ok"}],
  "unverified_citations": 0,
  "uncited": false,
  "model": "…",
  "cached": false,
  "prompt": null
}
```

## `POST /api/v1/ask/stream`

Same request body. The response is `text/event-stream`:

| Event | Data |
|---|---|
| `meta` | `{chunks, prompt?}` (sent first) |
| `token` | `{text}` (zero or more) |
| `done` | `{model, citations, unverified_citations, uncited, cached}` |
| `error` | `{code: llm_unavailable | llm_error | retrieval_error, message}` |

```bash
curl -N -X POST http://127.0.0.1:8000/api/v1/ask/stream \
  -H 'Content-Type: application/json' \
  -d '{"question":"What is the heap property?"}'
```

## `POST /api/v1/ask/agent/stream`

A slower, more careful path. Body: `{question, k (1-10), mode?, model?, temperature?}`. It always searches the server's index and is never cached. The workflow:

1. **rewrite** the question into a search query (it also searches the original wording, so a poor rewrite cannot hurt);
2. **retrieve**, then **grade**: the model says whether the passages are enough; if not, it searches once more with a query it suggests;
3. **answer** from the passages, streamed;
4. **verify** the citations; if the answer cited sources it was not given, it is **regenerated** once with the valid labels.

It uses at most 6 model calls per question (each counted against the daily cap). Planning failures (rewrite, grade) fall back to the plain behaviour; running out of quota stops the run with an `error` event.

| Event | Data |
|---|---|
| `step` | `{name: rewrite | retrieve | grade | answer | verify | regenerate, detail}` (one per stage, as it finishes) |
| `meta` | `{chunks}` (when answering starts) |
| `token` | `{text}` |
| `replace` | `{reason}`: discard the answer streamed so far; a corrected one follows |
| `done` | `{model, citations, unverified_citations, uncited, cached: false, llm_calls, regenerated}` |
| `error` | `{code: llm_unavailable | llm_error | retrieval_error | quota_exhausted | daily_limit, message}` |

Needs the optional `agent` extra (`pip install -e ".[agent]"`); without it the endpoint answers `503 agent_unavailable` and the rest of the API is unaffected.

## Indexing a PDF

```bash
curl -F "files=@data/uploaded_files/notes.pdf" http://127.0.0.1:8000/api/v1/sources/files
# {"files":["notes.pdf"],"urls":[],"job_id":"4f1c…"}
curl http://127.0.0.1:8000/api/v1/jobs/4f1c…
# {"status":"done","result":{"indexed":1,"skipped":0,"failed":0,"chunks_added":212}, ...}
```

## Retrieval only

```bash
curl 'http://127.0.0.1:8000/api/v1/search?query=hash%20collisions&k=3'
```

Returns `{"chunks": [...]}` with the same `Chunk` objects as above; useful for debugging retrieval without a model key.

## Limits

Flashcards, progress and history are stored in `data/study.db` (`STUDY_DB`); there are no accounts. Uploads: allowed types only, `%PDF-` signature checked, `MAX_UPLOAD_MB` (50) per file, bounded file count. Requests: `RATE_LIMIT_PER_MIN` (60) per IP, answered with `429` in the standard error shape.
